# 环境配置：让教程里的 AI 真正跑起来

> 本教程第 13/14 章讲"私有化部署"和"用黄金集评测研判器"。本文档告诉你**怎么把环境配通**，让 `scripts/golden_eval.py` 能用上真正的 LLM。
> **不绑定任何特定机器**——Windows / macOS / Linux 通用。你**不配 AI 也能学完前 14 章**：脚本默认走内置离线规则研判器。配 AI 只为体验"LLM 研判器"那一档。

---

## 0. 前置要求（通用）

| 项目 | 要求 |
|------|------|
| Python | 3.9 及以上（任意系统） |
| git | 可选，仅克隆仓库时需要 |
| AI 运行时 | 二选一：①本机装 Ollama 等本地运行时 ②一个云模型 API Key |
| 硬件 | 本地跑模型看规模（见第 4 节）；用云模型只需能联网 |

---

## 1. 两条路线怎么选

| 维度 | 路线 A：本地（Ollama 等） | 路线 B：云模型（API） |
|------|--------------------------|----------------------|
| 费用 | 免费（吃本机资源） | 按量付费 |
| 数据出域 | **不出域**（契合本教程"数据不出域优先"） | 日志/上下文发往厂商 |
| 硬件要求 | 需要一定内存/显存 | 无，任意能联网的机器 |
| 上手难度 | 装一次，长期免费用 | 注册拿 key，即用 |
| 适合 | 有独显/大内存、重视隐私 | 本机无显卡、想立刻跑 |

---

## 2. 路线 A：本地 Ollama（推荐，免费、离线）

### 2.1 安装（按系统选一条）

- **Windows**：`winget install Ollama.Ollama`，或去 https://ollama.com 下载 `.exe` 双击安装
- **macOS**：官网 `.pkg`，或 `brew install ollama`
- **Linux**：`curl -fsSL https://ollama.com/install.sh | sh`

装完 Ollama 会自动起一个本地服务（默认监听 `127.0.0.1:11434`）。

### 2.2 拉一个模型

```bash
ollama pull qwen2.5:7b          # 中文友好，入门够用（约 4.7GB）
# 机器资源充裕（独显 / 32G 内存）建议：
ollama pull qwen2.5:14b         # 输出更稳，尤其吐 JSON 更听话
ollama pull qwen2.5-coder:14b   # 若要真读代码找漏洞
```

> 其他可选：`deepseek-r1:8b`（推理型）、`llama3.1:8b`（英文强）。模型名以 `ollama list` 显示为准。

### 2.3 验证能用

```bash
ollama run qwen2.5:7b
```
能进入对话即成功。Ollama 自带 **OpenAI 兼容接口**，base_url 固定为：

```
http://localhost:11434/v1
```

## 3. 路线 B：云模型（本机无显卡时最省事）

任意支持 OpenAI 协议的工具（本教程脚本、Cursor、Continue、Aider、OpenClaw……）都认**三个环境变量**：

| 厂商 | `OPENAI_BASE_URL` | `OPENAI_MODEL` | Key 获取 |
|------|------|------|------|
| DeepSeek | `https://api.deepseek.com/v1` | `deepseek-chat` | platform.deepseek.com |
| 通义千问 | `https://dashscope.aliyuncs.com/compatible-mode/v1` | `qwen-plus` / `qwen-max` | dashscope.console.aliyun.com |
| 智谱 GLM | `https://open.bigmodel.cn/api/paas/v4` | `glm-4-flash` / `glm-4-plus` | open.bigmodel.cn |

把 Key 填进 `OPENAI_API_KEY`，另外两变量照表填即可，用法和本地完全一致。

---

## 4. 模型规模怎么选（通用参考）

| 用途 | 推荐规模 | 资源占用（本地） |
|------|----------|------------------|
| 纯研判 / 写报告 / 辅助思考 | 7B–14B | 7B≈6GB、14B≈10–12GB 显存 |
| 读代码找漏洞、写利用脚本 | 14B–32B | 32B≈20GB+ 显存 |
| 无独显 | 本地 7B（CPU 能跑但慢），或走云模型 | 看内存 ≥16GB |

> 规律：**本地有卡就 14B 起步；没卡直接云**。小模型（7B）跑 `golden_eval.py` 可能因吐 JSON 不稳而解析失败，遇到就升 14B。

---

## 5. 接到本教程

### 5.1 让 `golden_eval.py` 用 LLM 研判器

**Windows (PowerShell)**
```powershell
cd ai-alert-triage
$env:OPENAI_BASE_URL="http://localhost:11434/v1"   # 云模型填第 3 节对应地址
$env:OPENAI_MODEL="qwen2.5:7b"
$env:OPENAI_API_KEY="ollama"                       # 本地随便填；云填真实 key
python scripts/golden_eval.py
```

**macOS / Linux (bash/zsh)**
```bash
cd ai-alert-triage
export OPENAI_BASE_URL="http://localhost:11434/v1"
export OPENAI_MODEL="qwen2.5:7b"
export OPENAI_API_KEY="ollama"
python3 scripts/golden_eval.py
```

### 5.2 自检步骤

1. **先验证离线能跑**：不设置 `OPENAI_BASE_URL` 直接 `python scripts/golden_eval.py`，应输出 `match_rate = 15/15`（内置规则研判器，纯离线）。
2. **再切 LLM**：设好第 5.1 的三个变量再跑，对比 `precision/recall` 与规则研判器的差异——这就是第 14 章"研判质量评测"的落地。
3. **聚类也能跑**：`python scripts/triage_cluster.py --top 12` 与 AI 无关，任意环境都可跑。

> 同样的三变量模式也适用于 `ai-pentest-guide` 等任意 OpenAI 兼容工具——配一次，处处通用。

## 6. 排错（跨平台）

- **Windows 控制台中文乱码**：交互前设 `PYTHONIOENCODING=utf-8`
  - PowerShell：`$env:PYTHONIOENCODING="utf-8"`
  - bash/zsh：`export PYTHONIOENCODING=utf-8`
  （本教程脚本内部已 `sys.stdout.reconfigure(utf-8)`，但你自己敲命令时仍建议设。）
- **连不上 `11434`**：Ollama 服务没起 → `ollama serve`（Windows/macOS 一般开机自启）。
- **云模型返回 401**：Key 错或 `OPENAI_BASE_URL` 漏了 `/v1` 后缀。
- **模型名不对**：必须以 `ollama list` / 厂商模型列表里的字符串完全一致（含 `:7b` 这种标签）。
- **LLM 研判器分数掉到 0**：小模型没吐出合规 JSON，解析失败 → 换 14B 或收紧 prompt。

---

## 7. 安全与边界

- **敏感数据走本地**：日志/上下文若含真实告警，优先本地模型（路线 A），不要发往云厂商。
- **Key 不进仓库**：API Key 用环境变量，不要写进代码或提交到 git（仓库根已建议 `.gitignore`）。
- **本教程只做检测与研判**，不提供攻击载荷；案例均用脱敏样本。
